## 배운 것
- HashMap 내부 구조: 해시 함수 → 버킷 인덱스 → 충돌 처리(체이닝) → 리사이징. 평균 O(1)
- "보수(complement) 찾기" 패턴: target − 현재값을 맵에서 O(1) 조회
- 공간 O(n)으로 시간 O(n²) → O(n)을 사는 트레이드오프
- 정규화된 키(canonical key): 같은 그룹이면 반드시 같아지는 대표값을 설계해서 맵의 키로 쓴다
- 카운팅 키 O(k)가 정렬 키 O(k log k)보다 이론상 우위 (실측은 상수 때문에 역전 가능)
- `char + int`는 `int`로 승격 → `(char)('a' + j)` 캐스팅 필요
- `computeIfAbsent(key, k -> new ArrayList<>()).add(x)` — "없으면 만들고 이어서 쓰기"를 조회 1번에
- 메모리 beats%는 JVM 기본 사용량 때문에 노이즈, 무시

## 막혔던 부분 / 실수
- `nums[i] <= target` 필터를 넣었다가 음수 케이스에서 틀림
  - 원인: **제약 조건을 안 읽고** "값은 양수겠지"라고 가정함 (`-10^9 <= nums[i]`)
  - 교훈: 제약 조건에 근거 없는 최적화/필터는 넣지 않는다
- 합을 저장만 하고 안 읽는 `int[][]`는 불필요한 O(n²) 메모리였음 (첫 브루트포스)
- (49) 키 만들 때 `for (int j : arr)`로 값만 꺼내서 "어떤 글자인지"(인덱스)를 잃음 → "ab"와 "ac"가 같은 키가 되는 버그. 손으로 따라가기(3단계)로 잡음
- 브루트포스 정의가 아직 어려움 (4단계 비워둠) — "정의 그대로면 뭘 다 해봐야 하지?" 연습 계속

## 문제 분석 순서 (해부 프레임워크)
1. 입출력 정의 — 무엇을 반환? (값이 아니라 **인덱스**)
2. **제약 조건 읽기** — 값 범위(음수!), n 크기(→ 복잡도 예산), 보장 사항("정답 정확히 하나", "같은 원소 두 번 사용 금지")
3. 예제 손으로 풀기 — [3,3] 같은 중복 케이스 발견
4. 브루트포스 먼저 말하기 + 복잡도
5. 병목 찾기 — "짝을 찾는 반복 탐색" → O(1) 조회 필요 → HashMap
6. 코딩 → 예제 검증 → 복잡도 진술
