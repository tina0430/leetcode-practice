## 268에서 나온 것

- 말하면서 풀어도 시간이 늘지 않았다. 12:42는 704를 조용히 푼 12:15와 같은 수준이다
- 잘한 것: 코딩 전에 접근을 다 말함, 공식을 n=3으로 검산함, n(n+1)/2가 int 안에 드는지(5 × 10^7 < 2^31) 소리 내어 확인함
- 빠진 것: 기각한 대안 한 문장(HashSet은 O(n) 공간, XOR도 가능). 엣지 케이스 답이 "최대 크기 10k"였는데 정확성 엣지는 빠진 수가 0일 때(`[1]`)와 n일 때(`[0]`)다
- 이름: `sum`이 끝에는 빠진 수가 되므로 `missing`으로 바꿈. main이 비어 있었고 6단계 칸과 복잡도 칸이 비어 있었다 (복잡도 칸 네 번째 누락). 리뷰 후 채움

## 232에서 나온 것

- 힌트: 모의 면접관 프롬프트는 "hint라고 말할 때만 질문 하나"였는데, 내용이 정답(두 스택 + 앞이 필요할 때만 이동)이었다. 5단계 탐색은 내 것이 아니다. 실전 면접관은 한 칸씩 준다: 스택 하나로 뭐가 안 되나 → 되돌리는 도구 → 매번 뒤집어야 하나
- 이름: 두 번째 스택을 `queue`라고 불러서 `queue.push(stack.pop())`이 읽는 사람을 멈추게 했다. 말하면서 스스로 "check queue는 헷갈린다"고 감지하고 메서드는 고쳤으나 필드는 못 고쳤다. 리뷰 후 `in`/`out`, `refillOutIfEmpty`
- `java.util.Stack`은 Vector 기반이라 모든 메서드가 synchronized(매 호출 잠금)이고 가운데 삽입이 열려 있다. `ArrayDeque`가 관례. 카드 36 내용인데 실전에서 회수 못 함
- amortized 논증을 말로는 "normalized"라고 했다. 문장으로: 각 원소는 push 1회, 이동 1회, pop 1회로 총 3회, n번 연산에 3n → O(1). amortized와 average case의 차이: 전자는 어떤 호출 순서여도 성립하는 총합/n
- 테스트를 예제 밖까지 스스로 붙였다 (empty 전후, 추가 push 후 순서). 되묻기 3회("can you say that again", "you mean …")
- 6단계 칸이 또 전부 비었다. 268 직후였다

## 덱에서 나온 것

- 2의 보수: "반전 + 1" 레시피가 세 번째로 샜다. 4비트 16개 패턴을 전부 나열한 표(0000=0 … 0111=7, 1000=-8 … 1111=-1)와 "-x = 16 - x, 반전 = 15 - x"라는 유도를 주니 바로 이해했다고 함. 수치 관계는 레시피가 아니라 전체 나열 + 정의로 준다는 08-13 관찰의 두 번째 사례. 카드 32의 정답과 질문을 유도·검산 포함으로 바꿈
- 파생 질문에서 카드 41 신설: `Integer.MAX_VALUE + 1`은 `MIN_VALUE`(-MAX가 아니라 한 칸 더 음수), 704의 `(lo + hi) / 2`가 터지는 자리
- putIfAbsent가 boolean을 돌려준다고 답함(카드가 노린 함정 그대로). put 계열은 이전 값, compute 계열은 현재 값
- 개방 주소법 이름이 또 안 나옴. 어원 훅: 자리가 열려 있다(open addressing) vs 자리가 닫혀 있고 사슬을 단다(chaining)
