## 막혔던 부분

- **입력을 변형하는 풀이의 대가를 몰랐다.** `cur.val = 100001`은 호출자의 리스트를 파괴한다. 같은 리스트로 두 번 호출하면 두 번째는 무조건 `true`가 되고, 제약이 바뀌면 조용히 틀린다. 채점기는 호출 후 리스트를 안 보지만 면접관은 본다. 물었어야 할 질문은 **"입력을 변형해도 되나요?"**
- **`head`를 순회 커서로 썼다.** 반환값이 `boolean`이라 이번엔 결과가 맞았지만, 머리를 반환하는 문제에서 같은 습관이면 그 자리에서 버그다. 순회는 `cur`
- 잉여 가드 3줄(`head == null`, `head.next == null`, `head == head.next`)이 전부 아래 루프에 이미 포함돼 있었다. 판정 기준: **그 가드를 지웠을 때 깨지는 케이스를 하나라도 댈 수 있나**
- `contains` + `add`로 조회를 두 번 했다. `Set.add`가 boolean을 반환한다 (219에서 `map.put` 반환값을 스스로 찾아낸 것과 같은 패턴)
- 2단계에 제약을 `0 < node 개수 < 10^4`로 적었다. 지문은 `[0, 10^4]`이고 대괄호는 **양 끝 포함**이다. 08-05에 `[1, 100]`을 `1 < size < 100`으로 읽은 것과 같은 자리
- 복잡도 칸을 O(n)/O(n)인 채로 두고 follow-up까지 진행했다 (완료 직전 단계 누락 재발)
